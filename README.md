# Roudio

A personal app that turns a Plaud Note Pro's all-day recordings into transcripts,
notes and a searchable day. Start with `docs/roudio-brief.md`; architecture is in
`docs/architecture/`, the build plan in `docs/build/build-plan.md`.

## Layout

```
apps/android/          Kotlin + Jetpack Compose (Gradle)
apps/web/              React + TypeScript + Vite
services/backend/      FastAPI api + job worker (Python, uv)
packages/design-tokens tokens.json → Compose theme + CSS variables (+ Lexend)
packages/api-spec      openapi.json, generated by the backend
```

## Tools

uv, Node 24 + pnpm, Postgres 17, JDK 21, ffmpeg, Android Studio (SDK in
`~/Library/Android/sdk`).

## Everyday commands

```bash
pnpm install                       # web + token tooling

# Backend (services/backend)
cp .env.example .env               # then fill in what you have
createdb roudio && createdb roudio_test
uv run alembic upgrade head
uv run roudio-api                  # http://localhost:8000 (docs at /docs)
uv run roudio-worker                # processing, Drive backup, digests (needs ffmpeg)
uv run roudio-reprocess            # write every uploaded recording up again (after adding keys)
uv run roudio-vad-report day/*.ogg --out /tmp/dropped  # speech detector: kept vs dropped, clips to hear
uv run pytest                      # uses roudio_test; pipeline tests need ffmpeg
uv run ruff check . && uv run mypy src tests

# After changing the API: regenerate the spec and the web types
uv run roudio-openapi && pnpm --filter @roudio/web api:types
# (Android regenerates its Kotlin client on every build.)

# Design tokens: edit packages/design-tokens/tokens.json, then
pnpm tokens

# Web (apps/web)
cp .env.example .env.local
pnpm --filter @roudio/web dev      # http://localhost:5173

# Android (apps/android)
./gradlew :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb reverse tcp:8000 tcp:8000      # phone reaches the local backend at 127.0.0.1:8000
./gradlew :app:assembleFast        # for the owner's phone: R8-optimised, not debuggable, same key
adb install -r app/build/outputs/apk/fast/app-fast.apk
```

Android reads per-machine settings from `apps/android/local.properties` (git-ignored):

```properties
roudio.apiUrl=http://127.0.0.1:8000
roudio.googleServerClientId=<web/backend OAuth client ID>.apps.googleusercontent.com
```

## Deploying (Railway)

Project **roudio** in the **Quality Performance** workspace, with `production` and
`staging` environments. Each has Postgres, an `audio` bucket (Amsterdam), `api`,
`worker` and `web`. Every push to `master` deploys both environments.

| | production | staging |
| --- | --- | --- |
| api | https://api-production-59d9.up.railway.app | https://api-staging-d3f1.up.railway.app |
| web | https://web-production-bb1235.up.railway.app | https://web-staging-d0c3.up.railway.app |

Infrastructure is code: `.railway/railway.ts`. Preview and apply changes with a
project token for the target environment:

```bash
export RAILWAY_TOKEN=$(sed -n 's/^RAILWAY_TOKEN_PRODUCTION=//p' .env.railway)
railway config plan
railway config apply
```

`.env.railway` (git-ignored) holds `RAILWAY_API_TOKEN` (a workspace token; the
CLI doesn't accept those, but Railway's API does) and per-environment project
tokens. Secrets (`SESSION_SECRET`, `DRIVE_TOKEN_KEY`, Google and Plaud keys)
are set as shared variables in each environment, never in the file. Staging
and production have different secrets.

Known gap: `railway config plan` currently answers "Unauthorized" with the
staging token, so staging was created as a copy of production. Re-check after
CLI updates.

## Processing keys

The worker transcribes with ElevenLabs Scribe v2 and writes up with OpenAI (decisions 5 and 8).
Set these in Railway (shared variables, both environments) and in `services/backend/.env`:

```properties
ELEVENLABS_API_KEY=…
OPENAI_API_KEY=…
```

Without them, deployed recordings wait ("Writing up isn't set up yet") and are retried every hour.
Locally the stand-in transcriber and AI run instead. `PIPELINE_FAKES=true` makes a deployed server
use the stand-ins too, for end-to-end checks; their write-ups are obviously fake, so switch it off
and run `roudio-reprocess` (or tap "Try again now") once the real keys are in.

Speech detection uses FireRedVAD; the Docker image downloads its weights. Locally, download them
into `services/backend/models/FireRedVAD/VAD/` (see the Dockerfile for the URLs and checksums) and
set `VAD_MODEL_DIR=models/FireRedVAD`, or leave it unset for a simple loudness detector.

## Secrets

Keys live in Railway variables and in local `.env` / `.env.local` /
`local.properties` files, all git-ignored. Never commit them, and never paste
real recordings into the repo.
